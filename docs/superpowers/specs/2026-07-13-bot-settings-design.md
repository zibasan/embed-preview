# 設計書: Bot設定機能 (ブラックリスト・ホワイトリスト制御)

この設計書では、Botのリンクプレビュー機能をチャンネル、ユーザー、ロール単位で制限するための設定機能について定義します。

---

## 1. 目的と要件

### 目的

ユーザー（主にサーバー管理者）がBotの自動リンクプレビュー機能の動作を制御できるようにする。

### 要件

- **アクセス制御の種類**: チャンネル、ユーザー、ロール
- **制御ロジック (ブラックリスト・ホワイトリスト)**:
  - 判定対象（チャンネル、送信ユーザー、送信ユーザーの持つロール）に対して評価する。
  - ホワイトリストが設定されている（空でない）場合: ホワイトリストに含まれる対象のみプレビューを許可する。
  - ホワイトリストが空の場合: ブラックリストに含まれる対象のプレビューを拒否し、それ以外を許可する。
- **データ保存**: ギルド（サーバー）IDごとに設定値を保持し、ローカルの `data/settings.json` にJSON形式で保存・永続化する。
- **設定変更インターフェース**:
  - `/settings`（引数なし）: 現在の設定一覧を ComponentV2 の `Container` で美しく表示し、変更用の対話的UI（セレクトメニュー等）を提供する。
  - `/settings type:<whitelist|blacklist> action:<add|remove> [channel] [user] [role]`: 引数を直接入力して、コマンド一発で設定を変更できる。

---

## 2. アーキテクチャとデータ構造

### データ保存形式 (`data/settings.json`)

```json
{
  "guilds": {
    "123456789012345678": {
      "blacklist": {
        "channels": [],
        "users": [],
        "roles": []
      },
      "whitelist": {
        "channels": [],
        "users": [],
        "roles": []
      }
    }
  }
}
```

### 設定マネージャー (`SettingsManager`)

設定データの読み書きと、判定ロジックをカプセル化した `SettingsManager` クラスを `src/utils/settingsManager.ts` に作成します。

- **メモリキャッシュ**: ファイルアクセスを最小限にするため、メモリ上に設定データをキャッシュします。
- **非同期書き込み**: 設定変更時はメモリキャッシュを更新した上で、非同期（競合防止のため簡易キューイング）でファイルに書き込みます。
- **主要メソッド**:
  - `load()`: `data/settings.json` を読み込む。存在しない場合は空の構造を作成。
  - `save()`: 設定をファイルに保存する。
  - `getSettings(guildId: string)`: 指定ギルドの設定を取得する（初期値の補完含む）。
  - `setSettings(guildId: string, settings: GuildSettings)`: 指定ギルドの設定を保存する。
  - `isAllowed(guildId: string, channelId: string, userId: string, roleIds: string[])`: 指定されたコンテキストでプレビューが許可されているかを判定する。

## 3. スラッシュコマンド `/settings` の設計

### コマンド引数定義

- `type` (オプショナル / Choices: `whitelist`, `blacklist`)
- `action` (オプショナル / Choices: `add`, `remove`)
- `channel` (オプショナル / Channel型)
- `user` (オプショナル / User型)
- `role` (オプショナル / Role型)

### コマンドハンドラロジック (`src/commands/settings.ts`)

#### A. 引数入力時の直接処理

1. 引数の組み合わせバリデーション:
   - `type` と `action` が指定されているが、`channel` / `user` / `role` のいずれも指定されていない場合はエラー。
   - `channel` / `user` / `role` のいずれかが指定されているが、`type` または `action` が指定されていない場合はエラー。
2. 正常な場合、指定されたターゲットのIDを抽出し、`SettingsManager` を通じて該当リスト（例: `blacklist.channels`）へ追加または削除します。
3. 更新完了メッセージを返します。

#### B. 引数未入力時の対話的UI処理

1. 現在の設定情報を `SettingsManager` から取得。
2. `ContainerBuilder` を使用して、現在のブラックリスト・ホワイトリストの登録状況をスタイリッシュに表示。
3. 登録されている項目がある場合、それを削除するための「セレクトメニュー」を `ActionRowBuilder` で作成して追加します。
   - 例: 「ブラックリストからチャンネルを削除」セレクトメニュー
4. メッセージを送信します。
5. ボタンやセレクトメニューのインタラクション（`InteractionCreate`）をリッスンし、選択された項目をリストから削除する処理を行います。

---

## 4. 判定ロジックの統合

リンクプレビューを実行する以下の2箇所で、`SettingsManager.isAllowed` による判定を追加します。

1. **メンション時のプレビュー判定** (`src/events/messageCreate.ts`):
   - メッセージ送信時の `channel.id`、`author.id`、送信ユーザーが持つロールID of 配列を取得し、`isAllowed` を呼び出します。許可されていない場合は処理を中断します。
2. **手動コマンドによるプレビュー判定** (`src/commands/preview.ts`):
   - スラッシュコマンド実行時の送信コンテキストについて同様に `isAllowed` を呼び出し、不許可の場合は「このチャンネル/ユーザー/ロールではプレビューが許可されていません」と返します。

  - 引数バリデーションの境界値テスト。
